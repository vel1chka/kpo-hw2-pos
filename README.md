# Модуль «ПОС» (Преподавательская Оценка Студентов)

Консольное приложение на Go для учёта студентов, настройки рубрикатора, выставления оценок, расчёта итога по 10-балльной шкале и выгрузки ведомости в CSV/JSON.

## Запуск и тесты

```bash
go run main.go   # запуск CLI (пункт 1 — готовый сквозной демо-сценарий)
go test ./...    # юнит-тесты инвариантов и расчёта итога
```

## Архитектура и DI

Используется **Clean Architecture (Ports & Adapters)**. Зависимости направлены строго внутрь — `domain` не зависит от консоли, файлов и способа хранения:

```text
adapters (CLI, Storage, Export) ──▶ application (Facade) ──▶ domain (Models, Service, Ports)
```

- `main.go` — Composition Root (ручной DI: создаёт in-memory репозитории, передаёт их в фасад, а фасад — в консольный UI).
- `internal/domain` — модели и инварианты (`models.go`), расчёт итога (`calculator.go`), интерфейсы хранилищ (`ports.go`), тесты (`domain_test.go`).
- `internal/application` — сценарии использования (`facade.go`).
- `internal/adapters` — in-memory репозитории и экспорт (`storage.go`), консольное меню и таблицы (`console.go`).

## Доменная модель (DDD)

- **Ubiquitous Language:** `Student`, `Rubric`, `Criterion`, `Weight`, `Evaluation`, `CalculateFinalScore`.
- **Entity vs Value Object:**
  - *Entities:* `Student` (идентификатор — `Email`), `Evaluation` (связка `studentEmail + criterionName`, повторная оценка обновляет балл).
  - *Value Objects:* `Email` (непустой, содержит `@`), `Weight` (в диапазоне `(0, 1]`), `Criterion`, `Rubric` (возвращает копию среза, чтобы нельзя было изменить критерии снаружи).
- **Инварианты:** непустые имена, `maxScore > 0`, уникальные названия критериев и сумма весов `= 1.0`, балл строго в `[0, maxScore]`, оценка ставится только по критерию из текущей рубрики. При смене рубрики оценки не удаляются автоматически (чтобы можно было добавить новый критерий без потери данных); для полного сброса есть отдельный пункт меню с подтверждением.
- **Repository и Domain Service:** порты (`StudentRepository`, `EvaluationRepository`, `RubricRepository`) описаны в `domain/ports.go`, а реализованы в `adapters/storage.go`. Расчёт итога вынесен в сервис `CalculateFinalScore` (`calculator.go`), так как зависит сразу от рубрики и набора оценок студента.

## Паттерны GoF

| Группа | Паттерн | Где | Зачем |
| :--- | :--- | :--- | :--- |
| Порождающие | **Builder** (+ конструкторы `New*`) | `domain/models.go` (`RubricBuilder`) | Пошаговая сборка рубрики с проверкой уникальности критериев и суммы весов `= 1.0`; конструкторы закрывают создание невалидных объектов. |
| Структурные | **Facade** | `application/facade.go` (`AssessmentFacade`) | Единая точка для всех сценариев: консоль не работает напрямую с репозиториями и расчётом. |
| Поведенческие | **Template Method** | `adapters/storage.go` (`ExportPipeline`) | Общий каркас выгрузки (получить данные → отформатировать → записать файл) с подстановкой `FormatCSV` или `FormatJSON`. |

## Роль ИИ

Архитектуру, доменную модель, инварианты и сценарии продумывал самостоятельно (с консультацией железного наставника). ИИ в основном использовал как вспомогательный инструмент: подсказки по синтаксису Go, настройка консольного меню, а также ревью и доработка отдельных моментов (копирование среза в рубрике, обработка крайних случаев, набросок юнит-тестов, дизайн README).
